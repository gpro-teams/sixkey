# 所有者人工检查清单（Phase 0.x）

日期：2026-10-16。来源：`docs/history/PHASE0X-PLAN.md` §4.2，按合入后的真实代码更新。

这里列的是 CI 里的端到端测试做不到的检查。原因主要有三个：

- e2e 以标签页方式打开弹窗，拿不到真实工具栏弹窗的 `activeTab`；
- e2e 构建预先授予了剪贴板权限；
- 观感与计时要人来判断。

`scripts/bench/` 能通过 CDP 打开真实弹窗，但只用于手工计时。

**准备**

- 在 `extension/` 下运行 `npm run build`，加载生成的 `dist/`（未打包的生产构建）。不要用 `build:dev` 或 `build:e2e` 的产物：它们关闭了安装来源检查，e2e 构建还预先授予了剪贴板权限。
- 要固定扩展 ID 的几项（第 30–35 项的 Touch ID 和 Windows Hello、第 59 项的两台电脑）改用**测试版**：在 `extension/` 下运行 `npm run build:test`，加载 `dist-test/`。它就是商店版，只有三处不同：名字是"Sixkey (test)"；扩展 ID 固定为 `copndbnmkakfiohikpecmdaoldodaojc`，不管从哪个文件夹加载；不做安装来源检查（未打包加载时这个检查总会提示"不是从 Chrome 应用商店安装的"，所以检查这个提示的几项仍用 `dist/`）。第 52–57 项要的网页内提示只有开发版有，那几项写明了用开发版。
- 用一个新的 Chrome 配置文件，例如 `--user-data-dir=<新目录>`。Chrome 137 起的品牌版不再接受 `--load-extension`，请在 `chrome://extensions` 里打开"开发者模式"，再"加载已解压的扩展程序"。
- 每一项都写了预期结果。与预期不符的，记下截图和步骤。

---

1. **首次运行（中文、英文各走一遍，在干净的配置文件里）**
   - 点工具栏图标。
     - 预期：欢迎页除了语言按钮，只有"开始（先设置主密码）"和"从备份文件恢复"两个按钮，没有"不设密码"。
   - 点"开始"。
     - 预期：设置页在新标签页里打开向导，依次是：主密码（自己设的在前，"帮我生成"在后；不到 12 个字符等不可用；低于 50 位时有警告，点"仍然使用"后"继续"才可用，见第 26 项）→ 恢复密钥（可复制、可存为文件，必须勾选"我已保存恢复密钥"）→ "这个浏览器配置文件只有你在用吗？"两张卡片 → 完成。
   - 在主密码或恢复密钥这一步关闭标签页，再点图标。
     - 预期：仍是欢迎页，什么都没保存。
   - 选"只有我用（标准）"完成。
     - 预期：之后打开弹窗是解锁的。设置 › 安全 › 安全模式选中的是"只有我用（标准）"（闲置 15 分钟或锁屏时锁定）。
   - 在另一个新配置文件里选"会被共享、云同步或脚本控制"。
     - 预期：完成后出现清空剪贴板的引导，点"开启"弹出权限请求；在添加第一个账户之前仍是解锁状态。之后每次打开弹窗都要输入主密码，验证码被隐藏。

2. **真实网站上的"此网站"分级（真实工具栏弹窗）**
   - 添加一个 GitHub 账户，在编辑框的"网站"里登记 `github.com`；再添加一个名为 "GitLab" 的账户，不登记网站。
   - 在 `https://github.com` 上点图标。
     - 预期：GitHub 在最前，标着"此网站"。
   - 在 `https://gitlab.com` 上点图标。
     - 预期：GitLab 出现在"可能相关"下，不带"此网站"标签，旁边有"记住：gitlab.com 属于此账户"；点它、选域名、点"记住"之后，再打开就升为"此网站"。
   - （可选）仿冒主机名：在本机起一个服务，例如 `python3 -m http.server 8000`，打开 `http://github.com.localhost:8000/` 后点图标。
     - 预期：GitHub 不标"此网站"。它已登记域名，所以也不会出现在"可能相关"里。

3. **快捷键 Alt+Shift+K**
   - 在任意网页上按 Alt+Shift+K。
     - 预期：打开弹窗，和点图标一样（"此网站"分级也有效）。
   - 设置 › 外观。
     - 预期：显示当前绑定。快捷键被别的扩展占用时，在 `chrome://extensions/shortcuts` 里改；改完刷新设置页，显示随之变化。

4. **扫描本页**
   - 打开一个显示 otpauth 二维码的网页（例如在网页版 2FA 设置里），在弹窗的"添加"里点"识别当前页面的二维码"（空列表上的按钮叫"扫描本页"），用快捷键打开的弹窗再试一次。
     - 预期：直接进入弹窗内的确认页，显示名称、位数、周期，没有打开设置页。"添加并复制验证码"之后，剪贴板里的码在网站上能通过验证。页面可见区域没有二维码时，提示"当前页面的可见区域没有二维码"。

5. **粘贴截图**
   - 用系统截图把一个二维码复制到剪贴板，打开弹窗按 Ctrl+V（Mac 上是 ⌘V）。
     - 预期：进入确认页。同一个码再粘贴一次，显示"已在 Sixkey 中，名为 …，无需添加。"。

6. **主题与首帧**
   - 设置 › 外观里依次选"跟随系统"、"浅色"、"深色"。
   - 在"系统深色 + 手动浅色"和"系统浅色 + 手动深色"两种组合下，各反复打开真实弹窗 10 次。
     - 预期：没有一闪而过的另一种配色。输入框边框清晰可见。

7. **倒计时圆环（B1 的偏差，需要你认可）**
   - 打开弹窗，看验证码旁的圆环。
     - 预期：圆环每秒跳一格（不是连续动画），与秒数一致。最后 5 秒只有圆环和秒数变红（秒数闪烁），验证码数字保持原色。
   - 系统开启"减少动态效果"后再看一次。
     - 预期：同样正确。
   - **请决定**：每秒跳一格是否可以接受。PHASE0X-PLAN B1 原文要的是 CSS 连续动画。

8. **隐藏验证码（真实弹窗）**
   - 选"共享"模式，或在外观里开启"在弹窗中隐藏验证码"。
     - 预期：屏幕上没有数字，只有遮罩。点一行即复制，粘贴出来是正确的码。按住约半秒，或选中后按空格，显示该行 5 秒后再隐藏。"此网站"那一行也隐藏。
   - 紧凑密度。
     - 预期：行变矮，文字不被截断。

9. **导出**
   - 设置 › 备份，不填"主密码"。
     - 预期：加密备份、明文列表、导出所选账户三个按钮都不可用。
   - 填一个错误的主密码导出。
     - 预期：报错，安全记录多一条"主密码输错"。
   - 导出所选账户：勾选两个账户，文件密码用一个不同于主密码的密码，保存。然后在另一个新配置文件里点欢迎页的"从备份文件恢复"，打开这个文件。
     - 预期：文件名形如 `sixkey-selected-日期.json`；恢复之后只有那两个账户。
   - 在"添加账户"里粘贴一行 `name|JBSWY3DPEHPK3PXP|mypassword`，添加；然后导出明文列表。
     - 预期：预览说明其他列不会保存，列表里没有 `mypassword`。

10. **输错 3 次之后的提示**
    - 在弹窗里锁定，连续输错主密码 3 次，再输入正确的密码。
      - 预期：首个验证码出现之后，提示"自上次提示以来，主密码或恢复密钥输错 3 次"（`role=status` 的一行），没有"已自动恢复数据"横幅。再锁再解锁，提示不再出现。
    - 设置 › 安全 › 安全记录。
      - 预期：显示同样的事件与时间。清空要输主密码；清空后只剩一行"记录已清空"。

11. **安装来源横幅**
    - 用准备步骤里加载的 `dist/`（未打包的生产构建）。
      - 预期：弹窗与设置页顶部都显示"不是从 Chrome 应用商店安装的"。设置页里"此副本的扩展 ID"与 `chrome://extensions` 卡片上的 ID 一致，并说明还没有商店 ID。在上架（Phase 2）之前，这条横幅一直显示，这是预期的。

12. **忘记主密码的重设（在设置页标签页里）**
    - 弹窗锁定 → "使用恢复密钥" → "设置新密码"。
      - 预期：打开设置页标签页的"重设密码"。
    - 输入恢复密钥和新密码（两次），点"继续"。
      - 预期：显示新恢复密钥，并说明点"继续"之前什么都没改变。
    - 这时关闭标签页。
      - 预期：旧密码和旧恢复密钥照常能解锁，新恢复密钥打不开。
    - 重来一次，存好新恢复密钥，确认已保存，再点"继续"。
      - 预期：之后新密码能解锁，旧恢复密钥失效。

13. **"每次都锁定"下开着的设置页**
    - "共享"模式下，在设置页标签页里解锁，放置 16 分钟以上，不要刷新（刷新本身就会丢掉这个页面内存里的密钥）。然后在 设置 › 安全 › "新的恢复密钥"里输入主密码，点"生成新的恢复密钥"。
      - 预期：不显示新恢复密钥，页面回到锁定状态，顶部出现解锁栏。如果点的是导出或添加，只会显示"Sixkey 已锁定"，解锁栏要等页面重新读取状态之后才出现。在那之前，这个标签页一直持有密钥：docs/security/local-vault.md 如实写明，并建议用完就关闭设置页。

14. **旧设备密钥库**（只在还有 Phase 0 留下的库时做）
    - 预期：照常能打开；弹窗和设置页侧栏都有警告；"开启主密码"照常可用，开启时显示新恢复密钥，之后警告消失。

15. **性能观感**
    - 用 `scripts/bench/seed.mjs` 灌入 100 个和 500 个账户，在慢机或效率核上打开弹窗。
    - 跑一遍 `bash scripts/bench/run-set.sh <名字> dist warm proccold`，与 `docs/research/ux-study.md` 的表比较。
      - 预期：首个验证码没有明显的等待。这一项只作参考，不设门槛。

16. **字重**
    - 中英文各看一遍弹窗与设置页。
      - 预期：去掉两个字重之后，字形与粗细可以接受。

17. **（可选）Edge、Brave 或你在用的指纹浏览器**
    - 按 `docs/research/ux-study.md` §2.4 提到的清单（解锁、复制、扫描本页、导出、锁屏即锁）各走一遍；那一节没有逐条列出 10 步。
      - 预期：与 Chrome 一致。加载未打包的生产构建时会显示安装来源横幅。

18. **侧边栏模式（2026-10-20 新增，`docs/design/notes/SIDEPANEL-NOTES.md`）**

    自动化测试已在无头 Chromium 156 里用 DevTools 协议点过图标、打开过真实侧边栏（`test/e2e/sidepanel.spec.ts`），但下面这些只有真实浏览器、真实按键和人眼能确认。用"只有我用（标准）"的配置文件。
    - 设置 › 外观 › "点击图标时打开"选"侧边栏"，到 `https://github.com` 上点工具栏图标。
      - 预期：右侧打开 Sixkey 侧边栏，列表与弹窗相同；GitHub 显示在"此网站"或"可能相关"下。"扫描本页"能识别页面上的二维码。
    - 不点图标，切到另一个网站的标签页；再切回 github.com。
      - 预期：在另一个标签页上没有网站分组，搜索框下面改为一行提示"在此标签页上点击 Sixkey 图标……"（没有点过图标的标签页，浏览器不给网址）；在那里点"扫描本页"会失败，提示仍在。切回来后分组恢复、提示消失。在另一个标签页上再点一次图标，侧边栏不关闭，网站分组换成那个网站的。
    - 在 github.com 上打开侧边栏的"添加"，粘贴一个新的 GitHub 账户，确认页勾着"在 github.com 上优先显示"；不要按"添加"，切到另一个网站的标签页并在那里点图标，再回到侧边栏按"添加"。
      - 预期：确认页上那一行一直写的是 github.com；添加后它只在 github.com 上标为"此网站"，不在另一个网站上。
    - 按 Alt+Shift+K（或你设置的打开快捷键）。
      - 预期：打开的是侧边栏，不是弹窗，"此网站"同样有效。（快捷键在侧边栏模式下是否算"用户操作"，文档没有写明，这一项是关键。）
    - 侧边栏开着时，在一个弹窗或设置页里点"立即锁定"，或按 Alt+Shift+L。
      - 预期：侧边栏立刻显示锁屏，列表消失；锁屏上主密码没有"显示"按钮。在别处解锁后，侧边栏自己回到列表。
    - 把 设置 › 安全 › 自动锁定 改为闲置 60 分钟，打开侧边栏，16 分钟不碰任何 Sixkey 页面（编辑框开着也行）。
      - 预期：侧边栏回到锁屏，编辑框消失；其他 Sixkey 页面也锁定；设了 PIN 时 PIN 能解锁。期间每隔几分钟在侧边栏里按一下键或滚动一下，则不会锁定。
    - 自动锁定选"每次关闭弹窗时"，在侧边栏里解锁，关闭侧边栏再打开。
      - 预期：要重新输入密码（或 PIN）。另一个窗口里已解锁的侧边栏不受影响。
    - 开第二个窗口，在那里也点图标。
      - 预期：每个窗口各有自己的侧边栏；在任一处"立即锁定"，两个侧边栏都锁。之后在第一个窗口的侧边栏里解锁：第一个窗口回到列表；第二个窗口的侧边栏 5 分钟以上没碰过的话仍停在锁屏，在它里面点一下才显示列表（不会自己在另一块屏幕上亮出验证码）。
    - 在侧边栏锁屏上选"使用恢复密钥"，勾"显示"，输入几位，然后 2 分钟不碰侧边栏（或把窗口最小化）。
      - 预期：输入的内容被清空，"显示"取消。
    - 在侧边栏里复制一个验证码（已在 设置 › 剪贴板 开启清空）。
      - 预期：30 秒后剪贴板被清空。这一项确认 service worker 接受了侧边栏发来的消息（真实侧边栏的发送方没有 `tab`，这一点只在无头 Chromium 里测过）。
    - 外观里改回"弹窗"。
      - 预期：下一次点图标立刻是弹窗。弹窗页头有"在侧边栏中打开"按钮，点它打开侧边栏，弹窗关闭。
    - Service worker 停止后的第一次点击（最重要的一项：无头 Chromium 不检查"用户操作"规则，自动化测试证明不了这一点）：在 `chrome://serviceworker-internals` 里找到 Sixkey，点"Stop"（或让浏览器闲置一分钟以上），然后点图标；再停一次，按 Alt+Shift+K。
      - 预期：两次都直接打开侧边栏，不是弹窗；设置 › 高级 的诊断信息里没有 `toolbar action:` 开头的行。
    - 设好 PIN。侧边栏开着（已解锁），在一个网页的输入框里连续输入数字，同时在别处"立即锁定"或按 Alt+Shift+L。
      - 预期：数字都留在网页里，没有进入侧边栏的 PIN 输入框；设置 › 安全 里 PIN 的剩余尝试次数没有减少。
    - 自动锁定选"每次关闭弹窗时"，在侧边栏里解锁，然后在 Chrome 侧边栏顶部的下拉菜单里切到"阅读清单"或"书签"，再切回 Sixkey。
      - 预期：显示锁屏（如果直接显示列表，说明 Chrome 保留了页面，记下来：SIDEPANEL-NOTES §7）。
    - 侧边栏模式下，在一个已安装的网页应用（PWA）窗口或弹出式窗口里，用扩展菜单点 Sixkey，或按 Alt+Shift+K。
      - 预期：打开弹窗（那种窗口没有侧边栏），而不是什么都不发生；其他普通窗口仍然打开侧边栏。
    - 选"侧边栏"后完全退出并重启浏览器，第一次点图标。
      - 预期：直接打开侧边栏（service worker 在浏览器启动时重新设置；如果第一次仍是弹窗，记下来，这是 SIDEPANEL-NOTES §7 的未核实项）。
    - 设置 › 安全 › 安全模式 选"共享"。
      - 预期：开着的侧边栏自己关闭；图标打开弹窗；外观里不再提供"侧边栏"，改为一行说明；弹窗页头没有"在侧边栏中打开"；Chrome 自己的侧边栏菜单里也没有 Sixkey。
    - 把侧边栏拖到最窄和最宽，中英文、浅色深色各看一遍列表和锁屏。
      - 预期：没有被截断或溢出的文字，页头和底栏一直可见，只有列表滚动。
    - （可选）Edge、Brave、Opera 135 以上：重复第一项和"立即锁定"一项。
      - 预期：Edge 中切回原标签页时侧边栏可能不自动重新显示（Edge 的已知问题）；Brave 的 API 可用，但它自己的侧边栏里没有 Sixkey 的入口，只能从图标打开；没有这个 API 的浏览器里外观不显示这项设置，图标照常打开弹窗。

19. **从文件导入、拖放、摄像头、删除导出文件**（设置 › 添加账户；`docs/design/notes/IMPORT-FILE-NOTES.md`）
    - 点"选择文件"，选一个每行一条 `otpauth://` 链接的文本文件（例如 Google 身份验证器之外的应用导出的 `authenticator-uris-<日期>.txt`）。
      - 预期：文件名出现在列表里，预览显示账户数；密钥不出现在页面上。
    - 点"添加"。
      - 预期：出现"<文件名> 以明文保存着你的密钥。现在删除它吗？"，有"删除文件"和"保留"两个按钮（如果只显示"请自行删除"，说明这次没有拿到文件句柄：扩展页面里 Chrome 的文件选择器不可用，记下来）。点"删除文件"。
      - 预期：Chrome 弹出是否允许修改该文件的提示。选"允许"：文件从磁盘上消失（不在废纸篓里），页面显示"已删除"。再来一次选"不允许"：文件还在，页面说明没有删除并提示手动删除。
    - 选好文件后先在 Finder 里修改它（另存一次），再点"添加""删除文件"。
      - 预期：不删除，提示文件在读取之后被改动过。

    - 在工具栏弹窗里点"添加账户"的各个选项。
      - 预期：弹窗里没有摄像头；"上传二维码图片"等选项打开设置页的添加账户部分。

21. **TOTP 自动填写（第 1 阶段）：账户卡片上的填写按钮和快捷键 Alt+Shift+F**（`docs/design/notes/AUTOFILL1-NOTES.md`）
    - 准备：用 `npm run build` 的生产构建；在要测的账户的编辑框"网站"里登记登录页的域名（例如你截图里的 `ws.g.pro`）。测弹窗和侧边栏两种模式（设置 › 外观），每项各做一遍。
    - 在你截图里的那类登录页（ws.g.pro 的 Task Admin，有"TOTP 验证码（绑定后必填）"一栏）上点图标。
      - 预期：账户在"此网站"最前，卡片下面有深色按钮"把验证码填入此页面"，列表上方一行绿色的"此页面上找到了验证码输入框"。点按钮：验证码填进那一栏，用户名、密码、"记住我"都没动，页面没有自动提交；卡片上写"已填入验证码，请在页面上继续"。你自己点页面的"登录"，网站接受这个码。（这是你反馈的那一页，最关键的一项。）

      - 预期：卡片写"N 秒后填入新的验证码…"（有"取消"），之后填入的是下一个周期的码，网站接受；不会填一个马上过期的码。

    - 登录的第一步（只有用户名和密码，还没有验证码）。
      - 预期：那一行写"此页面上没有找到验证码输入框……"；点按钮得到同样的话，页面没有被改动。进入输入验证码的那一步后点"重新查找"，或直接点按钮，可以填。
    - 用你常用的真实网站各填一次（GitHub、Google 或 Microsoft、Cloudflare、阿里云或腾讯云或华为云、Gitee，一个用 React 或 Vue 做的管理后台，一个把验证码分成 6 格的网站，一个短信或邮箱验证码页面）。
      - 预期：能找到并填入；分成 6 格的逐格填入；短信或邮箱验证码页面不出现按钮，或出现"此页面可能要的是发给你的验证码"的提示。记下填不进去的网站和它的输入框写法（网页上右键"检查"，复制输入框那一行 HTML，不要含你的验证码）。
    - 登录框放在 iframe 里的网站（例如嵌入式的 Okta、Auth0 登录）。
      - 预期：能填。这一项很关键：Chrome 的文档没有写明 `activeTab` 是否覆盖跨域 iframe，自动化测试里的 Chromium 覆盖，真实 Chrome 的行为需要你确认；填不进去就记下网站和 Chrome 版本。

      - 预期：不填；图标出现"!"，提示说明原因；自动打开弹窗（侧边栏模式则打开侧边栏）让你选择或解锁，之后点填写。（Sixkey 现在要求 Chrome 140 或更高，都有 `action.openPopup`；它能否由快捷键触发，文档没有写明，这一项是关键。）

      - 预期：仍然能填，或至少给出"!"和提示，不会没有任何反应。
    - 快捷键冲突：看 `chrome://extensions/shortcuts`。

    - 把页面的语言和 Sixkey 的语言分别换成中文和英文，浅色和深色各看一遍弹窗和侧边栏（宽度拖到最窄和最宽）。
      - 预期：按钮、绿色那一行、提示都没有被截断或溢出；窄侧边栏里按钮可以换行。
    - 侧边栏模式下按 Alt+Shift+F，而页面只有两个账户登记、或已锁定。
      - 预期：图标出现"!"和提示。能否由快捷键自动打开侧边栏取决于浏览器是否还承认这次按键是"用户操作"（读取保险库、查看页面之后多半已不算），这一项是关键，记下结果；打不开时需要自己点图标。

    - 已锁定时按 Alt+Shift+F，等图标上的"!"消失后解锁 Sixkey，再把鼠标放在图标上。
      - 预期：提示是"Sixkey"，不再是"Sixkey 已锁定……"。填写成功后的"已填入验证码"提示也会在约 4 秒后消失。

    - 在一个 https 登录页上点填写。
      - 预期：不问"是否安全"；登记的是 `example.com` 而页面在 `login.example.com` 时，按钮写"在 login.example.com 上填写验证码"。

      - 预期：验证码仍会填进页面输入框（页面能看到），但弹窗和侧边栏里不显示。
    - 隐私：点填写后，打开该页面的开发者工具。

      - 预期：权限里有"在页面上运行脚本"之类的 `scripting` 不会显示在安装警告里；没有"读取和更改所有网站上的数据"；网站访问权限为"点击时"。

23. **锁定时按 Alt+Shift+F：解锁后自动填入（自动填写第 2 阶段补丁 1，2026-10-22 新增，`docs/design/notes/AUTOFILL2-NOTES.md`）**

    - 侧边栏模式，侧边栏开着并停在锁定界面时按 Alt+Shift+F。
      - 预期：侧边栏里出现那一行字；输入 PIN 后填入，侧边栏不关，卡片写"已填入验证码"。

24. **按网站开启验证码提示：Chrome 自己的权限弹窗、在 Chrome 里撤销、站点访问设置（自动填写第 2 阶段补丁 2，2026-10-22 新增，`docs/design/notes/AUTOFILL2-NOTES.md` §7）**
    - 准备：生产构建（或 dev 构建）；一个登记了账户、有验证码框的 https 网站（默认端口）。弹窗模式和侧边栏模式各做一遍。这一版里开启后页面里还不会出现提示（那是补丁 3），这里只检查权限和列表。
    - 在那个网站上点"填写"，验证码填好之后。

      - 点"允许"：卡片写"已在 … 上开启验证码提示"；设置 › 安全 › 自动填写 里有这个网站，状态"已开启"。

    - 在扩展菜单里选"在所有网站上"。
      - 预期：列表不变，没有任何网站因此被开启；Sixkey 也不会因此发出任何请求。再改回"点击时"。

25. **开启了验证码提示的网站上：点进验证码框后工具栏图标显示"1"（自动填写第 2 阶段补丁 3，2026-10-22 新增，`docs/design/notes/AUTOFILL2-NOTES.md` §9）**

      - 预期：图标不显示"1"。
    - 在没有开启的网站、http 页面、无痕窗口里点进验证码框。
      - 预期：图标都不显示"1"。
    - 显示"1"之后，在同一个标签页里打开另一个网址。
      - 预期："1"消失。
    - 在 `chrome://extensions` › Sixkey › 网站访问权限 里移除这个网站，然后刷新页面，再点进验证码框。

26. **自己设的主密码：第一次运行和重设（2026-10-22 新增，`OWNER-DECISIONS/15`，`docs/design/notes/OWN-PASSWORD-NOTES.md`）**
    - 在干净的配置文件里点"开始"，到主密码这一步。
      - 预期：两个密码框在前；"帮我生成"在它们下面，是不显眼的次要按钮。框下面写"至少 12 个字符。最好达到 50 位以上：几个随机词语就很好。"
    - 输入 11 个字符的密码（两个框都填）。
      - 预期："太短：至少 12 个字符。"，没有"仍然使用"，"继续"不可用。
    - 改成 `Password1234`（两个框都填）。
      - 预期："太容易猜：和常见密码太像。"，没有"仍然使用"，"继续"不可用。
    - 改成你自己好记的、13 个字符左右的密码（例如一个名字加两个词）。
      - 预期："估算强度 N 位，低于建议的 50 位。"；下面一个黄色框写"拷走这个浏览器配置文件的人可以离线猜，不限次数：一张显卡大约 …… 就能猜出这种强度的密码，显卡越多越快。"；"继续"不可用，按回车也不行。记下"……"是多久，以及这句话你看不看得懂。
    - 点"仍然使用"。
      - 预期：按钮变成选中（带勾），"继续"可用。没有弹出对话框。再改一个字符：选中取消，"继续"又不可用；改回去也要再点一次。

      - 预期：能解锁。记下从点"解锁"到出现列表大约多久（目标：这台 Mac 上不到半秒；如果手边有旧电脑，也记一下）。
    - 另一个干净配置文件里点"帮我生成"。

      - 预期：同样的警告和"仍然使用"；重设后用新密码能解锁。
    - 设置 › 备份 › 导出加密备份文件，文件密码填同一个低于 50 位的密码。
      - 预期：文件密码仍然要 50 位：显示"还差 … 位"，没有"仍然使用"，导出按钮不可用；"帮我生成"仍在密码框前面。

    - 设了 PIN 的话：修改密码之后锁定。

29. **恢复密钥分片：生成、打印、核对，用分片解锁和重设（2026-10-22 新增，2026-10-23 按评审修改，`docs/design/notes/SHAMIR-NOTES.md`）**
    - 设置 › 安全 › 密码与恢复 › 恢复密钥分片：保持"3 份中任意 2 份"和"生成新的恢复密钥，只以分片形式显示（推荐）"，输入主密码，点"生成分片"。
